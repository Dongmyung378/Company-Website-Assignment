# 시스템 구조

[프로젝트 소개](../README.ko.md)

## 요청 처리 과정

브라우저가 `public/`의 PHP 페이지에 접근하면 `config/bootstrap.php`가 세션을 시작하고 현재 직원 정보, 부서와 인증 버전을 조회합니다. 보호된 페이지는 공통 로그인 또는 관리자 검사를 거칩니다. POST는 CSRF 검사와 입력 검증 후 쿼리나 트랜잭션을 실행하고, 결과를 이스케이프한 HTML, 안전한 CSV 또는 리다이렉트로 응답합니다.

18개 PHP 엔드포인트가 요청과 화면을 처리하는 구조를 유지합니다. `lib/business.php`는 직원 및 휴가 입력을 검증합니다. 데이터베이스 설정은 CLI 전용이며, 스키마 설정 계정과 웹 실행 계정을 분리합니다. 실행 계정에는 스키마나 DB 계정을 관리할 권한을 부여하지 않습니다.

## 계정과 권한

일반 직원은 자신의 휴가와 비밀번호만 관리합니다. Executive 부서 소속은 이름을 기준으로 조회하며 시드 데이터의 부서 번호에 의존하지 않습니다. 요청마다 현재 계정과 소속을 확인하므로 삭제 또는 비활성 계정, 인증 버전이 다른 세션, 만료된 세션은 차단합니다. 부서나 비밀번호를 바꾸면 인증 버전을 증가시키며, 비밀번호를 바꾼 현재 세션을 제외한 다른 세션은 다음 요청부터 차단합니다.

로그인과 비밀번호 변경 시 세션 ID를 재발급합니다. 쿠키만 허용하는 엄격 모드, HttpOnly, SameSite=Lax와 HTTPS의 Secure 속성을 적용합니다. 기본 유휴 제한은 30분, 전체 세션 제한은 8시간입니다. POST는 세션별 무작위 CSRF 토큰을 확인하고 Origin이 있으면 일치 여부를 검사합니다. cross-site Fetch Metadata도 거부하며 Origin이 없어도 토큰은 필요합니다.

`login`은 비밀번호 해시 저장소이며 로그인 성공 이력이 아닙니다. `login_attempts`는 해시 처리한 계정과 IP 키로 반복 실패를 제한하고 오래된 기록을 정리합니다. 동시 요청이 제한을 우회하지 못하도록 계정과 IP 단위 잠금을 적용합니다. 계정별 임시 비밀번호는 처음 로그인할 때 변경해야 합니다. SQL로 직원을 직접 추가하면 트리거가 비밀번호 해시가 NULL인 비활성 계정을 만들며, 별도 발급 전에는 로그인할 수 없습니다.

## 데이터 무결성

| 작업 | 처리 경계 |
| --- | --- |
| 직원 추가 | DB가 ID를 발급하고 직원, 연락처, 트리거의 잔여 휴가 및 계정, 비밀번호 발급을 한 트랜잭션으로 저장 |
| 직원 수정 | 정확한 대상 ID를 잠금 조회하고 `row_version`을 비교한 뒤 직원과 연락처를 함께 수정, 부서 변경 시 인증 버전 증가 |
| 휴가 승인 | 저장된 Pending 신청을 잠금 조회하고 본인, 유형 및 일수를 계산해 충분한 잔여 일수에서 한 번만 차감 |
| 직원 삭제 | 저장 프로시저가 트랜잭션 안에서 전체 길이의 직원 정보를 기록하고 삭제하며 오류 발생 시 롤백 |
| 월별 부재 | 승인된 휴가 중 조회 월과 겹치는 구간만 선택하고 해당 월의 일수만 계산 |

Pending 신청은 일수를 미리 예약하지 않습니다. 여러 신청이 대기 중일 수 있지만, 승인 시 잔여 일수가 부족하면 상태와 잔여 일수를 바꾸지 않습니다. 반려는 일수를 차감하지 않습니다. 휴가는 시작일과 종료일을 포함한 달력 일수로 계산하며 주말도 포함하는 과제 규칙을 유지합니다. 날짜를 UTC의 날짜 값으로 다뤄 일광절약시간 전환에도 일수가 달라지지 않습니다.

급여는 기존 문자열 표현과 저장 값을 유지하고, 인상률 계산은 숫자로 저장된 급여에만 적용합니다. 보고서도 기존의 단순화한 보너스 및 공제식을 유지합니다. CSV 함수에는 빈 이스케이프 인자를 명시하고 수식으로 해석될 수 있는 텍스트 앞에 작은따옴표를 붙입니다. 이 경우 스프레드시트 안전성을 위해 내보낸 텍스트 표현이 달라집니다.

## 설정과 초기 이력

`database/schema.php`와 `database/objects.php`가 현재 스키마 및 DB 객체를 정의합니다. 설정 명령은 가상 CSV를 한 번만 가져오고 마이그레이션 버전을 기록합니다. 다시 실행해도 삭제한 직원을 복구하거나 기존 업무 데이터를 시드로 덮어쓰지 않습니다. 기존 DB는 데이터를 다시 넣지 않고 구조를 갱신합니다. 기본값이 아닌 기존 비밀번호는 유지하고, 알려진 초기 비밀번호만 개별 임시 비밀번호로 바꾸면서 이전 세션을 폐기합니다.

삭제 기록은 유지합니다. 보고서를 열 때 자동으로 3년 이상 된 기록을 삭제하던 동작은 CSRF 검사를 거치는 명시적인 POST 버튼으로 바꿨습니다. 초기 소스는 Git 이력에서, 개인 점검 자료는 소유자의 비공개 검토 폴더에서 보존합니다. 취약한 초기 코드를 공개 실행 사본으로 복제하지 않습니다. [보안 및 검증](SECURITY.ko.md), [DB 운영 안내](../database/README.ko.md)에서 자세한 내용을 확인할 수 있습니다.

## 검증 범위

프레임워크나 외부 인증, 클라우드, 메일 발송 서비스 없이 실행하는 학습 프로젝트입니다. 실제 운영에는 독립적인 권한 체계, MFA와 복구 정책, 비밀정보 및 백업 관리, 배포 환경의 TLS 점검, 업무상 보존 정책 등이 추가로 필요합니다. 이 저장소의 검증은 해당 운영 체계를 포함하지 않습니다.
