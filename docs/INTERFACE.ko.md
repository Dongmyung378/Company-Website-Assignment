# UI와 주요 사용 흐름

[프로젝트 소개](../README.ko.md)

실제 화면을 표시하는 PHP 페이지 17개에 공통 UI를 적용했습니다. `index.php`는 기존처럼 로그인 화면으로 연결합니다. 별도 프런트엔드 빌드 없이 로컬 CSS와 JavaScript, SVG를 사용하며 외부 글꼴이나 CDN을 요청하지 않습니다. 기존 주소, 데이터와 보안 검사 및 과제의 급여 계산 규칙은 유지합니다.

## 개선한 내용

| 영역 | 사용자가 확인할 변화 |
| --- | --- |
| 메뉴 | PC의 고정 메뉴와 현재 위치 표시, 본문 바로가기, 모바일 메뉴와 Escape 닫기 및 키보드 초점 복원 |
| 관리자 홈 | 실제 직원 수, 대기 신청, 당일 휴가와 사무실 수를 요약하고 팝업 대신 화면 안에 승인 안내 표시 |
| 직원 홈 | 자신의 잔여 휴가, 최근 처리 내역과 개인 업무 바로가기 |
| 직원 목록 | 이름과 이메일 검색, 펼칠 수 있는 상세 필터, 이름순 정렬, 필터를 유지하는 12명 단위 페이지 이동 |
| 직원 프로필 | 업무 및 연락처, 개인 정보와 비상 연락처를 구분하고 해당 직원의 수정 화면으로 바로 연결 |
| 직원 입력 | 필수 항목과 입력 조건 안내, 선택한 부서에 속하는 직책 표시, 날짜 제한과 오류 안내 |
| 휴가 | 시작일과 종료일을 포함한 달력 일수, 승인 후 예상 잔여량, 상태 배지와 신청 내역 |
| 보고서 | 명확한 필터, 요약 카드와 표의 내부 스크롤, 기존 급여 계산식과 CSV 유지 |
| 비밀번호 | 표시 전환과 새 비밀번호 일치 확인, 현재 비밀번호 및 최초 변경 의무 유지 |
| 제출 | 삭제 등 주요 작업의 확인 절차, 클릭한 작업명을 유지하는 중복 제출 방지 |

검색어의 `%`, `_`, `!`는 SQL 매개변수로 전달하고 일반 문자로 검색합니다. 유효하지만 큰 페이지 번호는 마지막 페이지로 이동하고, 잘못된 값과 배열형 입력 또는 범위를 벗어난 값은 거부합니다. 상세 필터를 적용한 경우 필터 영역이 자동으로 펼쳐집니다.

부서별 직책 표시와 휴가 미리보기는 입력을 돕는 기능입니다. 서버는 별도로 소속 관계, 계정 상태, 날짜와 잔여량, CSRF, 변경 버전과 트랜잭션을 검사합니다. JavaScript 없이도 서버 화면과 검증은 유지합니다. 넓은 표는 화면 전체가 아닌 패널 안에서 스크롤하며 모션 최소화 설정과 인쇄 화면도 지원합니다.

## 영어 기본과 한국어 선택

처음 접속할 때의 기본 언어는 브라우저 설정과 관계없이 영어입니다. 화면 상단에서 한국어를 선택할 수 있으며 호스트 전용 HttpOnly 및 SameSite=Lax 설정의 언어 쿠키로 선택을 유지합니다. 언어를 바꿔도 권한, 직원 ID, 저장된 처리 상태나 급여 값은 달라지지 않습니다. 검색 조건은 유지하고, 입력 중인 내용이 있으면 새로 불러오기 전에 확인합니다.

`lib/i18n.php`와 `lib/translations/*.ko.php`에서 영문 원문 및 이름이 있는 치환값을 관리합니다. 공통 용어는 한 곳에서 통일합니다. Annual leave는 연차 휴가, Sick leave는 병가, Personal leave는 개인 휴가입니다. 월별 보고서는 승인된 휴가를 집계하므로 결근이 아닌 월별 휴가 현황으로 안내합니다. Full-Time과 Part-Time은 각각 전일제와 시간제로 표현하며 정규직 여부를 임의로 해석하지 않습니다. 영국 국민보험번호는 한국의 주민등록번호로 바꾸지 않습니다.

메뉴, 입력 안내, 상태 표시와 오류, 클라이언트 미리보기를 한국어로 제공합니다. 직원 이름과 주소 및 사용자가 입력한 원본 데이터는 그대로 유지합니다. 브라우저 자체 날짜 선택기는 브라우저와 운영체제 언어를 따릅니다. CSV는 기존 영어 열 제목과 데이터를 유지하며 내보내기 화면에도 이를 안내합니다.

## 가독성과 디자인 일관성

로그인 화면과 관리자 및 직원 홈에서 정사각형 Kilburnazon 회사 일러스트를 자르지 않고 보여줍니다. 이미지에 어울리는 남색과 짙은 초록색, 은은한 회녹색 배경을 사용합니다. 본문과 이미지 설명은 그림 위에 겹치지 않게 별도의 영역에 배치합니다. 모바일에서는 로그인 입력란을 먼저 보여주고 이미지를 아래에 배치합니다.

정리한 `app.css`에서 패널, 입력 화면과 업무 카드의 공통 간격을 관리합니다. 일관된 SVG 아이콘과 차분한 아바타 색상, 구분되는 흰색 표면으로 업무 영역을 명확히 나눕니다. 급여 숫자는 오른쪽으로 정렬하고 넓은 표에는 가로 이동 안내를 표시합니다. 모바일 메뉴가 열리면 뒤쪽 화면을 조작하지 못하도록 처리합니다.

실제 렌더링된 글자와 배경 색상을 투명도까지 합성하여 [W3C 글자 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 및 [비문자 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)과 대조했습니다. 일반 글자 4.5:1, 큰 글자 3:1, 의미 있는 입력 경계와 아이콘 3:1을 적용합니다. 이 항목을 점검한 것이며 접근성 전체를 인증하는 것은 아닙니다.

## 로컬 로그인

기존 [설정 가이드](../database/README.ko.md)를 따릅니다. 로그인 정보는 비공개 로컬 파일로 제공하며 소스에 고정된 공개 비밀번호를 넣지 않습니다. 소유자의 로컬 데모 계정과 로그인 안내는 Git에서 제외한 실행 데이터입니다. 임시 비밀번호는 처음 로그인할 때 변경해야 합니다.

## 실행 및 화면 검증

현재 디자인은 **실제 브라우저 검사 1,288/1,288개를 통과**했습니다. **화면과 언어 및 크기 조합 90개**, **스크린샷 24개**를 확인했으며 두 언어에서 1440px PC와 390px 모바일을 검사하고 320px, 360px 및 768px도 보충 점검했습니다. 별도의 [HTTP, 보안, 업무 및 언어 검증](verification/company-design-regression.json)도 **121/121개를 통과**했습니다.

해당 화면 조합에서 글자 샘플 22,244개와 입력 예시 78개가 대비 기준을 통과했습니다. 측정된 최저 글자 대비는 **5.141:1**, 입력 예시 대비는 **5.461:1**이며 입력 경계 샘플 1,040개의 최저 대비는 **3.523:1**입니다. 기능성 SVG 샘플 882개, 글자 크기 샘플 22,582개, 버튼 및 아이콘의 내부 배치 98개도 확인했습니다. 판정하지 못한 배경이나 실패 항목은 남아 있지 않습니다. 숨겨진 요소, 비활성 요소와 장식 요소 등은 결과 파일에 명시한 기준에 따라 제외합니다.

- [현재 HTTP 및 언어 검증](verification/company-design-regression.json)은 전체 17개 화면의 두 언어 표시, 영문 기본값, 선택 유지, 치환값 누락, CSV 형식, 업무 처리의 무결성 및 권한 제한을 확인합니다.
- [현재 PHP 문법 검사](verification/company-design-php-lint.json)는 이번 디자인에서 변경한 PHP 5개 파일을 대상으로 합니다. 이전 [전체 PHP 문법 검사](verification/bilingual-php-lint.json)는 52개 파일을 확인한 기록입니다.
- [현재 브라우저와 스타일 검증](verification/company-design-browser.json)은 대비와 배치, 언어 선택, 미저장 입력 안내, 실제 폼 클릭, 휴가 미리보기, 스크립트와 자원 오류 및 테스트 프로세스 정리를 기록합니다.
- 이전 [영문 및 한국어 HTTP 검증](verification/bilingual-regression.json)과 [브라우저 검증](verification/bilingual-browser.json)은 검증 시점별 기록으로 보존합니다.
- 초기 [UI 회귀 검증](verification/ui-regression.json), [브라우저 기록](verification/ui-browser.json), [보안 수정 검증](SECURITY.ko.md)은 그대로 보존합니다.

폐기 가능한 `_test` 데이터베이스에서 실행합니다.

~~~sh
python tests/security_regression.py
~~~

선택 브라우저 검증에는 로컬 Microsoft Edge와 Python의 `websocket-client` 패키지가 추가로 필요합니다. 별도 브라우저 프로필과 테스트 계정을 사용하고 자체 서버 및 브라우저를 종료합니다.

~~~sh
python tests/browser_ui.py
~~~

Edge 설치 경로가 다르면 `--edge /path/to/msedge` 또는 `EDGE_BIN`으로 지정합니다. 두 스크립트 모두 `PHP_BIN`과 `PHP_ARGS_JSON`을 사용합니다. [검증 설정](SECURITY.ko.md)을 함께 참고하세요. 스크린샷은 Git에서 제외한 `var/ui-screenshots/`에 저장합니다. 비어 있는 영문 및 한국어 로그인 미리보기만 `docs/images/`에 선별하며 인증정보나 브라우저 프로필은 공개하지 않습니다.

화면 크기별 자동 검사와 시각 검토는 로컬 Edge의 해당 크기를 대상으로 했습니다. 접근성 인증이나 모든 브라우저 및 모든 길이의 내용에 대한 호환성을 보장하는 검증은 아닙니다. 기존 기능은 화면과 별도로 HTTP 및 동시 요청 검증도 수행합니다.
