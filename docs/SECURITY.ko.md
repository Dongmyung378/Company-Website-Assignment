서로 다른 PHP 프로세스 두 개와 독립적인 관리자 세션으로 실제 동시 요청을 보냈습니다. 같은 신청을 동시에 승인하면 한 번만 승인되고 나머지는 충돌로 거부됐습니다. 잔여량 5일에 각각 4일을 승인하는 요청이 동시에 도착해도 한 건만 승인돼 1일이 남고 다른 건은 Pending으로 유지됐습니다. 직원 두 명을 동시에 추가하면 서로 다른 ID와 연락처 및 계정, 잔여 휴가가 정상 저장됐습니다. 이는 특정 동시 처리 조건의 검증이며 장시간 부하 성능 측정은 아닙니다.

공개하는 자료는 비밀번호와 개인 환경 정보를 제외한 검증 결과입니다. 인증정보, 쿠키, 브라우저 프로필, 전체 HTTP 응답, 개인 로그 및 초기 점검 원본은 저장소에서 제외했습니다. 초기 소스는 Git 이력에, 최초 검토 자료와 상세 재현 기록은 소유자의 비공개 검토 폴더에 유지합니다.

## 다시 검증하기

[DB 설정 가이드](../database/README.ko.md)에 따라 `company_regression_test`처럼 이름이 `_test`로 끝나는 별도 DB와 새 실행 계정명(예: `company_regression_app`), 설정 계정을 준비한 뒤 실행합니다. MySQL 계정은 서버 전체에서 공유하므로 기존 실행 계정명을 다시 생성하는 요청은 거부합니다.

~~~sh
python tests/security_regression.py
~~~

Python 3.10 이상에서 표준 라이브러리로 실행하며 테스트가 자체 로컬 PHP 서버를 시작하고 종료합니다. PHP가 PATH에 없다면 `PHP_BIN`으로 지정합니다. 포터블 Windows 환경에서는 `PHP_ARGS_JSON`으로 확장 모듈 옵션을 전달할 수 있습니다.

~~~powershell
$env:PHP_BIN = 'C:/tools/php/php.exe'
$env:PHP_ARGS_JSON = '["-n","-d","extension_dir=C:/tools/php/ext","-d","extension=mysqli"]'
python tests/security_regression.py
~~~

웹 요청에는 제한된 실행 계정을 사용하고, 테스트 데이터 및 오류 주입 준비에만 설정 계정을 사용합니다. 테스트 직원은 정리하고 자체 서버를 종료하며 상세 결과는 Git에서 제외한 `var/security-regression.json`에 기록합니다. 위의 별도 마이그레이션 및 Edge 검증을 이 명령이 모두 실행하는 것으로 표시하지 않습니다.

## 실행 버전과 보안 공지

검증에는 PHP **8.5.12**, 공식 Windows 패키지 **8.5.12-1**, MySQL **8.4.13 LTS**를 사용했습니다. PC의 기존 PHP 설치나 MySQL 서비스는 변경하지 않았습니다. 임의의 PHP 또는 MySQL 8.x가 아닌 공급자의 보안 패치 버전을 사용하세요.

- PHP의 [2026년 10월 공지](https://www.php.net/archive/2026.php)와 [메모리 부족 처리 공지](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w), [상태 관리 공지](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp)를 기준으로 패치 버전을 선택했습니다. `php -v`가 같아도 Windows 재배포 패키지 번호가 다를 수 있습니다.
- 공급자 안내에 따라 `session.upload_progress.enabled=0`을 서버 시작 시 적용합니다. 현재 프로젝트는 업로드 진행률 기능을 사용하지 않습니다. [서버 INI 예시](../config/php-production.ini)와 로컬 및 테스트 실행 명령에 해당 설정이 있습니다.
- MySQL [8.4.13 변경 기록](https://dev.mysql.com/doc/relnotes/mysql/8.4/en/news-8-4-13.html)과 [10월 보안 공지](https://dev.mysql.com/community/security/advisories/2026-10-20/)를 기준으로 지원 중인 패치 버전을 검증했습니다. 최초 점검에서 사용한 MySQL 8.0.45는 최종 검증에 사용하지 않았습니다.

모든 입력이나 취약점의 부재를 보장하는 검증은 아닙니다. 실제 배포의 TLS와 프록시, 서버 및 OS 패치, 모든 스프레드시트의 수식 해석 방식, 전수 퍼징, 실제 개인정보 및 PHP 메모리 손상 취약점 공격은 검증 범위에 포함하지 않습니다. 파일 접근 권한과 백업 및 실제 업무의 보존 정책은 배포 환경에서 관리해야 합니다.
